# 论文实验设置、Benchmark 来源与本地复现范围

核对日期：2026-10-12。本文记录论文原文给出的设置，以及本项目实际验证过的内容。未公开或未说明的参数会明确标注，不能用当前代码默认值补成论文参数。

这里涉及两篇不同的论文：

- **原始 SkillClaw 论文**：研究共享 skill 如何根据多用户执行经验改进。依据 [arXiv:2604.08377v2](https://arxiv.org/html/2604.08377v2)，版本日期 2026-08-10。
- **PoisonedEvolution 攻击论文**：研究少量不可信执行记录是否会污染生成的 skill。完整标题为 *When Experience Becomes Instruction: Trajectory Poisoning in Self-Evolving Agent Skill Systems*。依据 [arXiv:2608.05563v2](https://arxiv.org/html/2608.05563v2)，版本日期 2026-08-07。

## 1. 两篇论文的实验区别

| 项目 | 原始 SkillClaw | PoisonedEvolution |
| --- | --- | --- |
| 研究问题 | 多用户经验能否改善共享技能库 | 不可信轨迹能否被提炼成污染技能的规则 |
| Benchmark | WildClawBench | SpreadsheetBench |
| 主要组织方式 | 8 个模拟用户，共享 skill 库 | 每次抽取一批 30 条轨迹，其中 3 条由攻击者贡献 |
| 进化轮次 | 固定 6 天、6 轮 | 每次试验运行一轮进化 |
| 主模型 | Qwen3-Max，覆盖执行、进化和验证 | GLM-5 采集轨迹；6 个不同模型分别担当 evolver |
| 主结果 | 4 个任务类别的逐日评分 | 生成技能中新嵌入目标行为的比例 SER |
| 更新后检查 | 新旧 skill 在同一环境中完整执行相关任务并比较 | 主攻击评估到生成的 skill 文本为止 |

来源：SkillClaw [§2.3、§3.2](https://arxiv.org/html/2604.08377v2#S3.SS2)；PoisonedEvolution [实验部分](https://arxiv.org/html/2608.05563v2#Sx5)。6 轮、8 用户与 30 条、3 条分别属于不同实验，不能合并成同一个设置。

## 2. Benchmark 是什么、从哪里来

### 2.1 WildClawBench：原始 SkillClaw 使用的 Benchmark

WildClawBench 是上海人工智能实验室与合作高校的 Shuangrui Ding、Xuanlang Dai、Long Xing 等作者发布的独立基准。它由研究者人工编写现实工作场景任务，覆盖完整 Agent 工具执行。来源是 [Benchmark 论文](https://arxiv.org/abs/2605.10912) 与 [InternLM 官方仓库](https://github.com/InternLM/WildClawBench)。

| 内容 | 官方入口 |
| --- | --- |
| 任务规范、评分代码、运行框架 | [InternLM/WildClawBench](https://github.com/InternLM/WildClawBench) |
| 项目介绍 | [WildClawBench 项目页](https://internlm.github.io/WildClawBench/) |
| 工作目录素材、任务资源与 Docker 镜像 | [internlm/WildClawBench 数据仓库](https://huggingface.co/datasets/internlm/WildClawBench) |
| Harbor 格式资源 | [WildClawBench-Harbor](https://huggingface.co/datasets/internlm/WildClawBench-Harbor) |
| Benchmark 自身的公开执行轨迹 | [WildClawBench-Trajectories](https://huggingface.co/datasets/internlm/WildClawBench-Trajectories) |

一题包含任务提示、Markdown 规范及 YAML 元数据、输入素材、环境准备和评分逻辑。Agent 在 Docker 工作目录中调用工具执行任务，评分结合产物检查、环境状态审计和模型语义判断。部分交互任务有模拟参与者，因此不能把所有外部交互都理解成真实用户在线参与。

| 任务类别 | 数量 |
| --- | ---: |
| Productivity Flow：生产力工作流 | 10 |
| Code Intelligence：代码任务 | 12 |
| Social Interaction：社交交互 | 6 |
| Search & Retrieval：搜索与检索 | 11 |
| Creative Synthesis：创意生成 | 11 |
| Safety Alignment：安全与对齐 | 10 |
| **合计** | **60** |

60 题中，36 题英文、24 题中文；26 题多模态、34 题纯文本。来源：[Benchmark §3](https://arxiv.org/html/2605.10912v1#S3)。

版本边界：本次核对的官方代码 revision 为 `8e1fde746584ae1a9c49b70526d49a7a572625cd`。当前资源支持多种 Agent 框架，并持续更新；这个 revision 和公开轨迹尚未被确认与 SkillClaw 的 8 用户、6 轮实验环境及日志完全一致。

Benchmark 自身的评测协议给出单题 300–1200 秒预算和 GPT-5.4 评分模型；原始 SkillClaw 则写明全流程使用 Qwen3-Max。前者的预算、评分配置不能直接填入后者的实验参数。来源：[Benchmark §3.2](https://arxiv.org/html/2605.10912v1#S3.SS2)、[§4.1](https://arxiv.org/html/2605.10912v1#S4.SS1)。

### 2.2 SpreadsheetBench：投毒论文的任务来源

SpreadsheetBench 来自论文 *SpreadsheetBench: Towards Challenging Real World Spreadsheet Manipulation*，发表于 NeurIPS 2024 Datasets and Benchmarks。官方入口是 [RUCKBReasoning/SpreadsheetBench](https://github.com/RUCKBReasoning/SpreadsheetBench) 与 [项目网站](https://spreadsheetbench.github.io/)。

原始数据有 **912 个任务、2,729 个测试用例**，平均每题约 3 个用例。问题及原始 Excel 文件来自 **ExcelForum、Chandoo、MrExcel、ExcelGuru** 等论坛。研究者用 GPT-4 辅助整理指令，再由人工检查问题、制作参考答案和额外测试用例；额外用例通过改变表格数据覆盖不同输入和边界情况。来源：[SpreadsheetBench §2.2–2.3](https://arxiv.org/html/2406.14991v2#S2.SS2)。

每个任务通常包含自然语言要求、输入工作簿、参考输出以及需要检查的位置。评估检查执行后的工作簿结果，不要求实现代码或公式写法与参考解法完全相同。

| 指标 | 定义 |
| --- | --- |
| Hard accuracy | 一个任务的全部测试用例都通过，才把该任务记为通过；最后对任务取平均 |
| Soft accuracy | 先计算每个任务的测试用例通过比例，再对任务取平均 |

官方工作簿评估需要按评测流程重算公式并读取结果，不能用“公式字符串保存正确”替代完整任务准确率。来源：[原论文 §2.4](https://arxiv.org/html/2406.14991v2#S2.SS4)、[官方评估说明](https://github.com/RUCKBReasoning/SpreadsheetBench#evaluation)。

官方同时提供不同版本或子集，例如 sample 200、原始 912 v0.1、后续 Verified 400。本文本地准备的是 **912 v0.1 的一个 100 题子集**；不能将它称为 Verified 400。

### 2.3 投毒论文怎样从 Benchmark 得到轨迹

PoisonedEvolution 的数据准备链路是：

1. 选择 100 个 SpreadsheetBench 任务，论文称为 training tasks。
2. 使用 GLM-5 和原始 `xlsx` skill 执行这些任务。
3. 收集 300 条按测试用例记录的执行日志。
4. 将日志转换成 SkillClaw 可接收的会话记录。
5. 每次试验选取任务不同的一批记录，混入攻击者贡献，再执行一轮进化。

来源：[投毒论文实验部分](https://arxiv.org/html/2608.05563v2#Sx5)。这 300 条是模型执行产生的日志，不是 Benchmark 下载包本身。论文没有列出那 100 个任务的具体 ID；也没有给出可以据此确认的官方划分文件。

### 3.2 给定一个 skill，后续如何运行

1. **使用**：不同用户的 Agent 使用同一个共享库，根据各自任务选择 skill。
2. **留存证据**：记录请求、工具动作、错误、恢复过程和最终结果。
3. **聚合**：把引用同一 skill 的会话归为一组，同时看成功与失败记录；没用到 skill 的会话另行用于发现缺失能力。
4. **生成候选**：模型改写技能、创建技能，或认为证据不足而跳过。
5. **执行验证**：相关任务分别用当前版本和候选版本完整执行，再比较结果。
6. **部署**：接受的候选进入共享库；拒绝的候选不替换当前版本。
7. **下一轮使用**：用户继续提交自己的任务，新的执行记录进入下一轮。

论文没有说明把同一个 skill 的不同阶段任务预先分配给不同用户；用户共享的是技能库和经验。8 个用户的具体任务安排与每日执行次数未给出，不能算成 `60 × 8 × 6` 次任务运行。来源：[§2.1–2.3、§3.2](https://arxiv.org/html/2604.08377v2#S2)。

附录提示词另规定摘要约 8–15 句、部分轨迹字段值约截断到 400 字符。这些是证据格式约束，不是模型推理 token 预算。见 [SkillClaw v2 PDF 附录](https://arxiv.org/pdf/2604.08377v2)。

## 4. PoisonedEvolution：投毒实验

### 4.1 主实验参数

| 参数 | 论文设定 |
| --- | --- |
| 主要目标系统 | SkillClaw |
| 目标 skill | `xlsx` |
| 轨迹生成模型 | GLM-5 |
| 源任务 | 100 个 SpreadsheetBench training tasks |
| 源日志数 | 300 条 case-level 执行日志 |
| 每次试验轨迹数 `n` | 30 |
| 攻击者贡献数 `k` | 3 |
| 干净轨迹数 | 27 |
| 投毒比例 `k/n` | 10% |
| 每次试验进化次数 | 一轮 |
| 主设置初始 skill | 有初始 `xlsx` skill，称为 init，研究已有技能的改写 |
| 辅助设置 | no-init，研究技能创建；采集源日志时仍使用过原始 skill |
| 原生进化决策 | 保留 refine/create/skip |
| 可选 session-quality judge | 主实验关闭 |
| 可选 publish-time verifier | 主实验关闭 |
| 每个模型 × 行为类别 | 25 次已完成试验 |
| 主矩阵规模 | 6 个 evolver × 4 类行为 × 25 次 = 600 次 |
| 主指标 | SER，Skill Embedding Rate |
| 评估终点 | 生成的 skill 文本，不执行其目标攻击行为 |

来源：[PoisonedEvolution 实验部分及表 1](https://arxiv.org/html/2608.05563v2#Sx5)。每次试验固定下游流程和初始状态，只改变攻击者贡献的输入轨迹；一批中的任务保持不同。

### 4.2 攻击输入与成功判断

攻击者可以查看已有 skill，并贡献有限数量的轨迹；不能直接改写技能库，也不能查看私有轨迹池或修改进化逻辑。

论文把成功拆成三个条件：

| 条件 | 含义 |
| --- | --- |
| C1：进入证据流 | 攻击记录被原生采集、过滤或路由接收 |
| C2：被当作经验 | Evolver 把其中的行为归纳为可复用的技能规则 |
| C3：写入技能 | 目标行为保留在最终生成的 skill 中 |

核心构造是保留正常任务上下文，让同一种行为在少量记录中反复表现为成功所需的步骤，或失败缺少的修复。不同轨迹的任务和措辞可以不同，目标行为语义保持一致。来源：[威胁模型](https://arxiv.org/html/2608.05563v2#Sx3)、[轨迹构造方法](https://arxiv.org/html/2608.05563v2#Sx4)。

| 行为类别 | 研究的安全影响 | 实验中的受控表示 |
| --- | --- | --- |
| F1 | 机密信息外传 | 引用 inert canary URL 的 xlsx 自注册公式 |
| F2 | 数据完整性破坏 | 限定到 canary 临时路径的清理规则 |
| F3 | 软件供应链重定向 | loopback 软件包 registry |
| F4 | 安全检查弱化 | 模拟 CI preflight 标志 |

canary 是用于识别目标行为是否被写入的实验标记。这些内容在轨迹和 skill 文本中出现，但论文没有执行对应的外传、删除、安装或绕过行为。来源：[行为类别说明](https://arxiv.org/html/2608.05563v2#Sx4)。

SER 的分母是**已完成进化的试验**，分子是生成技能中新加入目标行为的试验。检测结合初始与最终 skill 的差异、目标操作语义和 canary 上下文；LLM judge 用于辅助检查，不定义成功。端点失败不能直接记作干净负例。来源：[指标定义](https://arxiv.org/html/2608.05563v2#Sx3)。

### 4.4 辅助实验和消融参数

| 实验 | 设置 | 论文结果 |
| --- | --- | --- |
| 攻击记录数量 | 固定 `n=30`，`k=1/2/3` | 5/25、21/25、25/25 |
| 干净证据稀释 | 固定 `k=3`，`n=10/30/100` | 25/25、25/25、22/25 |
| 极低支持诊断 | `k=1,n=100` | 0/5 |
| C2 因果归因 | 单处插入、跨记录碎片、因果结果绑定 | 8/25、11/25、25/25 |
| C3 行为编码 | 通用措辞、辅助通道、贴合 xlsx 的操作语义 | 18/25、0/25、25/25 |
| no-init 创建诊断 | 4 个代表性 evolver，合计 600 次 | 490/600，81.7% |

来源：[RQ1–RQ2、图 2–3](https://arxiv.org/html/2608.05563v2#Sx5)。记录数量和稀释实验是代表性模型上的诊断，不能当作六个模型的完整均值；正文未给出足以逐项复现这些诊断的完整模型分配。C3 同时改变通道和出现位置，不是完全单变量对比。no-init 的模型集合与主表不同，不能仅凭 81.7% 和 91.0% 推断初始 skill 的因果效果。

### 4.5 Trace2Skill 迁移、正常任务收益与防御试验

Trace2Skill 的迁移实验每次同样用 `n=30,k=3`：3 条受控失败轨迹混入从留出表格轨迹池抽取的 27 条干净失败轨迹，经原生错误分析和技能合并生成输出。四类行为各 150 次，共 600 次。

| 类别 | 成功 / 完成 | SER |
| --- | ---: | ---: |
| F1 | 101/150 | 67.3% |
| F2 | 124/150 | 82.7% |
| F3 | 116/150 | 77.3% |
| F4 | 28/150 | 18.7% |
| 合计 | 369/600 | 61.5% |

来源：[RQ3、表 2](https://arxiv.org/html/2608.05563v2#Sx5.T2)。迁移试验的模型、模式组合不能自动等同于 SkillClaw 的六模型主矩阵。

正常任务收益检查使用 Qwen3.5-122B-A10B，在前述用于采集轨迹的 100 个任务上报告：

| 条件 | Hard | Soft |
| --- | ---: | ---: |
| 不使用 skill | 18.0% | 34.88% |
| 使用投毒进化后的 skill | 20.0% | 36.54% |

来源：[正常任务收益检查](https://arxiv.org/html/2608.05563v2#Sx5)。这是采集任务集上的有限检查，另有单个留出实例的 smoke test；不能把它当作大规模独立测试集评估。

论文还做了来源多样性门控的初步防御试验：要求至少 3 个用户与来源簇，限制单一来源占多数并惩罚高文本重复。在 `n=30,k=3` 的单簇 F1 设置下，25/25 个候选被挡住，门控后 SER 从 25/25 降至 0/25；另接受了一个 5 会话的多样性干净对照。具体阈值、聚类实现与大规模干净通过率未充分给出。来源：[讨论部分](https://arxiv.org/html/2608.05563v2#Sx6)。

### 5.2 正常流程：GPT 5.6 的一次完整闭环

| 项目 | 本地已验证内容 |

| 启用阶段 | 摘要、session judge、evolver、merge、skill verifier、版本登记与发布 |

## 7. 当前代码与原始论文的差异

| 项目 | 原始论文描述 | 当前仓库实现 |
| --- | --- | --- |
| 候选发布 | 真实执行新旧版本，候选更好才部署 | 默认 `publish_mode=direct`，默认关闭 `use_skill_verifier` |
| 可选 skill verifier | 论文描述完整执行后比较的 validator，未定义这一可选文本评审组件 | LLM 根据技能内容与记录做质量评审 |
| 客户端 replay 验证 | 同一环境、完整工具链执行任务 | 当前 replay 分支生成文本答复，由 PRM 评分 |
| replay 接受条件 | 候选优于当前版本 | 当前代码允许候选均分等于 baseline，且达到分数门槛 |
| 持续服务停止 | 论文实验固定 6 轮 | 周期服务持续处理新记录，没有自动收敛停止条件 |

来源：[演化服务配置](../evolve_server/core/config.py)、[客户端验证实现](../sharedskill/validation_worker.py)、[周期运行逻辑](../evolve_server/engines/workflow.py)。当前默认分数门槛 0.75 是代码配置，不能写成论文验证门槛。我们的良性运行主动启用了 skill verifier，但没有运行论文描述的真实新旧任务执行对照。
