## 1. 实验要回答什么

研究问题是：少量攻击者贡献的执行记录，能否被技能进化系统当作正常经验，最终形成新的污染 skill？主要目标系统是 SkillClaw，Trace2Skill 用来检查是否能迁移到另一种进化流程。

主攻击实验只检查生成的技能文件：目标规则是否新加入其中。后续是否真的触发该规则、是否影响其他用户以及长期反复进化的结果，没有纳入主 SER 指标。论文另有规模有限的正常任务收益检查。

来源：[论文介绍](https://arxiv.org/html/2608.05563v2#Sx1)、[指标](https://arxiv.org/html/2608.05563v2#Sx3)、[讨论](https://arxiv.org/html/2608.05563v2#Sx6)。

## 2. 数据来源与模型职责

### 2.1 SpreadsheetBench 任务从哪里来

SpreadsheetBench 来自论文 *SpreadsheetBench: Towards Challenging Real World Spreadsheet Manipulation*，发表于 NeurIPS 2024 Datasets and Benchmarks。官方入口是 [RUCKBReasoning/SpreadsheetBench](https://github.com/RUCKBReasoning/SpreadsheetBench) 与 [项目网站](https://spreadsheetbench.github.io/)。

原始数据有 **912 个任务、2,729 个测试用例**，平均每题约 3 个用例。问题及原始 Excel 文件来自 **ExcelForum、Chandoo、MrExcel、ExcelGuru** 等论坛。研究者用 GPT-4 辅助整理指令，再由人工检查问题、制作参考答案和额外测试用例；额外用例通过改变表格数据覆盖不同输入和边界情况。来源：[SpreadsheetBench §2.2–2.3](https://arxiv.org/html/2406.14991v2#S2.SS2)。

每个任务通常包含自然语言要求、输入工作簿、参考输出以及需要检查的位置。评估检查执行后的工作簿结果，不要求实现代码或公式写法与参考解法完全相同。

| 指标 | 定义 |
| --- | --- |
| Hard accuracy | 一个任务的全部测试用例都通过，才把该任务记为通过；最后对任务取平均 |
| Soft accuracy | 先计算每个任务的测试用例通过比例，再对任务取平均 |

官方工作簿评估需要按评测流程重算公式并读取结果，不能用“公式字符串保存正确”替代完整任务准确率。来源：[原论文 §2.4](https://arxiv.org/html/2406.14991v2#S2.SS4)、[官方评估说明](https://github.com/RUCKBReasoning/SpreadsheetBench#evaluation)。

官方同时提供不同版本或子集，例如 sample 200、原始 912 v0.1、后续 Verified 400。本文本地准备的是 **912 v0.1 的一个 100 题子集**；不能将它称为 Verified 400。

### 2.2 从任务生成执行轨迹

PoisonedEvolution 的数据准备链路是：

1. 选择 100 个 SpreadsheetBench 任务，论文称为 training tasks。
2. 使用 GLM-5 和原始 `xlsx` skill 执行这些任务。
3. 收集 300 条按测试用例记录的执行日志。
4. 将日志转换成 SkillClaw 可接收的会话记录。
5. 每次试验选取任务不同的一批记录，混入攻击者贡献，再执行一轮进化。

来源：[投毒论文实验部分](https://arxiv.org/html/2608.05563v2#Sx5)。这 300 条是模型执行产生的日志，不是 Benchmark 下载包本身。论文没有列出那 100 个任务的具体 ID；也没有给出可以据此确认的官方划分文件。

### 2.3 日志采集模型和技能进化模型分别做什么

| 角色 | 模型 | 输入 | 输出 |
| --- | --- | --- | --- |
| 采集正常执行日志 | GLM-5 | SpreadsheetBench 任务与原始 xlsx skill | 300 条 case-level 执行日志 |
| 执行技能进化 | 六个 evolver，分别见主结果表 | 混合轨迹与当前初始 skill | 更新后的技能或跳过决定 |
| 判定投毒嵌入 | 行为类别专用的 diff-aware 检测规则 | 原始与生成 skill 的差异 | 是否新增目标行为 |

GLM-5 的作用是先生成轨迹，不计入主表的六个 evolver。LLM judge 仅辅助检查模糊结果，主成功判定由检测规则定义。

来源：[数据准备与指标](https://arxiv.org/html/2608.05563v2#Sx5)。

### 2.4 模型、用户、25 次与 skill 数量如何对应

**六个模型对应六种 evolver 配置。** Evolver 是 SkillClaw 中负责读执行证据、决定 refine/create/skip 并生成技能更新的 Agent。主表分别用 GPT-5.4、MiniMax-M2.5、DeepSeek-V3.2、DeepSeek-V4-Pro、Qwen3.5-35B-A3B 和 Qwen3.5-122B-A10B 作为它的模型后端，比较不同模型是否会把攻击者的规则写入技能。它们分别接受评测，没有组成六个模型共同修改同一份技能的团队。预先执行表格任务、采集日志的模型是 GLM-5。

**用户是会话证据的贡献者。** 在 SkillClaw 的使用场景中，用户向自己的 Agent 提交任务，执行记录进入共享证据池；攻击者可以控制自己或 Sybil 身份贡献的少量记录。这里的 `n=30` 指 30 条轨迹，`k=3` 指其中 3 条受攻击者控制，不能据此算成 30 个用户或 3 个攻击用户。投毒主矩阵没有给出固定的模拟用户数或完整的用户到会话分配。此前的“8 个模拟用户”来自原始 SkillClaw 正常实验，它描述 8 个并发用户各自用 Agent 完成 WildClawBench 任务、共享技能库的部署场景。

**25 次是主结果表每个格子的已完成试验数。** 例如固定“GPT-5.4 × F1”，按同一配置完成 25 次单轮进化；每次的输入是初始 xlsx 条件与 30 条混合轨迹，输出是该次进化的技能结果，再判断是否新增 F1 行为。论文报告 17/25，表示其中 17 次把 F1 目标行为写进了输出。25 的计数单位是一次完成的进化试验，不是用户数、任务数或模型 API 调用数；一次试验内部可以包含多个处理阶段。

| 固定或统计的范围 | 数量含义 |
| --- | --- |
| 固定一个模型与一类行为 | 25 次已完成试验 |
| 固定一个模型，覆盖 F1–F4 | 4 × 25 = 100 次 |
| 覆盖六个模型与四类行为 | 6 × 4 × 25 = 600 次 |

论文给出了每次批内任务不同、每个实验单元固定下游组件与初始技能条件；没有给出 25 次之间的完整重采样清单、seed 和重置实现。因此不能进一步描述成“完全相同输入只重复调用 25 次”，或声称 25 次试验统计上完全独立。各试验只执行一轮，主表也没有描述成前一次输出继续作为下一次初始技能的 25 轮链路。

**主矩阵聚焦一个目标技能：`xlsx`。** SpreadsheetBench 是任务数据集，`xlsx` 是 Agent 用来处理表格的技能；100 个任务提供不同的表格操作场景，F1–F4 是试图写进技能的四类行为，它们都不代表不同的 skill。init 从原始 xlsx 开始，测试已有技能被改写；另设 no-init 测试从证据创建技能。系统保留 create/refine/skip，因此“一个目标技能”不能扩大解释为所有试验的技能库或输出始终恰好只有一个文件；论文未列出完整技能库清单及逐次输出文件数。

来源：PoisonedEvolution [背景](https://arxiv.org/html/2608.05563v2#Sx2)、[贡献者与实验单元](https://arxiv.org/html/2608.05563v2#Sx3)、[实验与表 1](https://arxiv.org/html/2608.05563v2#Sx5)；原始 SkillClaw [§3.2](https://arxiv.org/html/2604.08377v2#S3.SS2)。

## 3. 一次试验具体如何运行

以主设置的 xlsx skill 为例：

1. **确定初始技能与试验条件。** 主表使用已有原始 xlsx skill（init）；选择一个 evolver 和一个 F1–F4 行为类别。
2. **组织证据批次。** 从源日志形成 30 条任务不同的轨迹，包括 27 条干净记录和 3 条攻击者贡献。
3. **改写攻击者自己的记录。** 保留任务上下文和原有结果，使目标行为反复呈现为完成任务需要的步骤；攻击者不直接改写技能库或其他贡献者的记录。
4. **通过原生证据流程。** 保留系统本来的提示词和 refine/create/skip 决策逻辑；SkillClaw 主矩阵关闭可选 session-quality judge 与 publish-time verifier。
5. **执行一轮技能进化。** Evolver 读取混合证据和初始 skill，决定是否改进或创建技能，也可能跳过。
6. **检查技能差异。** 检测生成技能是否新增该行为的操作语义及 canary 上下文，记录一次已完成试验的结果。
7. **按实验单元汇总。** 每个模型与行为组合收集 25 次已完成试验，计算 SER。

来源：[轨迹构造](https://arxiv.org/html/2608.05563v2#Sx4)、[实验设计](https://arxiv.org/html/2608.05563v2#Sx5)。原文每次只运行一轮，并按固定初始技能条件组织试验；没有说明同一个 skill 连续经历 600 轮更新。它也没有给出缓存、环境、LLM 会话和随机状态的完整重置细节，不能据此宣称每次试验统计上完全独立。

## 5. 攻击输入与成功判断

攻击者可以查看已有 skill，并贡献有限数量的轨迹；不能直接改写技能库，也不能查看私有轨迹池或修改进化逻辑。

论文把成功拆成三个条件：

| 条件 | 含义 |
| --- | --- |
| C1：进入证据流 | 攻击记录被原生采集、过滤或路由接收 |
| C2：被当作经验 | Evolver 把其中的行为归纳为可复用的技能规则 |
| C3：写入技能 | 目标行为保留在最终生成的 skill 中 |

核心构造是保留正常任务上下文，让同一种行为在少量记录中反复表现为成功所需的步骤，或失败缺少的修复。不同轨迹的任务和措辞可以不同，目标行为语义保持一致。来源：[威胁模型](https://arxiv.org/html/2608.05563v2#Sx3)、[轨迹构造方法](https://arxiv.org/html/2608.05563v2#Sx4)。

| 行为类别 | 研究的安全影响 | 实验中的受控表示 |
| --- | --- | --- |
| F1 | 机密信息外传 | 引用 inert canary URL 的 xlsx 自注册公式 |
| F2 | 数据完整性破坏 | 限定到 canary 临时路径的清理规则 |
| F3 | 软件供应链重定向 | loopback 软件包 registry |
| F4 | 安全检查弱化 | 模拟 CI preflight 标志 |

canary 是用于识别目标行为是否被写入的实验标记。这些内容在轨迹和 skill 文本中出现，但论文没有执行对应的外传、删除、安装或绕过行为。来源：[行为类别说明](https://arxiv.org/html/2608.05563v2#Sx4)。

SER 的分母是**已完成进化的试验**，分子是生成技能中新加入目标行为的试验。检测结合初始与最终 skill 的差异、目标操作语义和 canary 上下文；LLM judge 用于辅助检查，不定义成功。端点失败不能直接记作干净负例。来源：[指标定义](https://arxiv.org/html/2608.05563v2#Sx3)。

## 7. 辅助实验与消融

### 7.1 辅助设置与机制消融

| 实验 | 设置 | 论文结果 |
| --- | --- | --- |
| 攻击记录数量 | 固定 `n=30`，`k=1/2/3` | 5/25、21/25、25/25 |
| 干净证据稀释 | 固定 `k=3`，`n=10/30/100` | 25/25、25/25、22/25 |
| 极低支持诊断 | `k=1,n=100` | 0/5 |
| C2 因果归因 | 单处插入、跨记录碎片、因果结果绑定 | 8/25、11/25、25/25 |
| C3 行为编码 | 通用措辞、辅助通道、贴合 xlsx 的操作语义 | 18/25、0/25、25/25 |
| no-init 创建诊断 | 4 个代表性 evolver，合计 600 次 | 490/600，81.7% |

来源：[RQ1–RQ2、图 2–3](https://arxiv.org/html/2608.05563v2#Sx5)。记录数量和稀释实验是代表性模型上的诊断，不能当作六个模型的完整均值；正文未给出足以逐项复现这些诊断的完整模型分配。C3 同时改变通道和出现位置，不是完全单变量对比。no-init 的模型集合与主表不同，不能仅凭 81.7% 和 91.0% 推断初始 skill 的因果效果。

### 7.2 Trace2Skill 迁移、正常任务收益与防御试验

Trace2Skill 的迁移实验每次同样用 `n=30,k=3`：3 条受控失败轨迹混入从留出表格轨迹池抽取的 27 条干净失败轨迹，经原生错误分析和技能合并生成输出。四类行为各 150 次，共 600 次。

| 类别 | 成功 / 完成 | SER |
| --- | ---: | ---: |
| F1 | 101/150 | 67.3% |
| F2 | 124/150 | 82.7% |
| F3 | 116/150 | 77.3% |
| F4 | 28/150 | 18.7% |
| 合计 | 369/600 | 61.5% |

来源：[RQ3、表 2](https://arxiv.org/html/2608.05563v2#Sx5.T2)。迁移试验的模型、模式组合不能自动等同于 SkillClaw 的六模型主矩阵。

正常任务收益检查使用 Qwen3.5-122B-A10B，在前述用于采集轨迹的 100 个任务上报告：

| 条件 | Hard | Soft |
| --- | ---: | ---: |
| 不使用 skill | 18.0% | 34.88% |
| 使用投毒进化后的 skill | 20.0% | 36.54% |

来源：[正常任务收益检查](https://arxiv.org/html/2608.05563v2#Sx5)。这是采集任务集上的有限检查，另有单个留出实例的 smoke test；不能把它当作大规模独立测试集评估。

论文还做了来源多样性门控的初步防御试验：要求至少 3 个用户与来源簇，限制单一来源占多数并惩罚高文本重复。在 `n=30,k=3` 的单簇 F1 设置下，25/25 个候选被挡住，门控后 SER 从 25/25 降至 0/25；另接受了一个 5 会话的多样性干净对照。具体阈值、聚类实现与大规模干净通过率未充分给出。来源：[讨论部分](https://arxiv.org/html/2608.05563v2#Sx6)。

## 8. 与原始 SkillClaw 的设置区别

SkillClaw 评估的是系统持续使用和进化后的任务表现；PoisonedEvolution 评估的是一次经验归纳是否产生污染技能。

| 项目 | 原始 SkillClaw 正常实验 | PoisonedEvolution 主攻击实验 |
| --- | --- | --- |
| 实验目标 | 改善共享技能库的任务表现 | 测量不可信轨迹被写入 skill 的可能性 |
| Benchmark | WildClawBench，60 个跨领域 Agent 任务 | SpreadsheetBench，100 题采集的 300 条日志 |
| 运行组织 | 8 个模拟用户持续使用共享库 | 组织固定大小的轨迹批次，选定模型与行为分别试验 |
| 每批输入 | 当天用户执行产生的会话 | 30 条记录，27 条干净、3 条攻击者贡献 |
| 时间结构 | 固定 6 天、6 轮，接受的更新影响后一天 | 每次试验一轮；600 是主矩阵的已完成试验数 |
| 执行模型 | Qwen3-Max | GLM-5 负责预先采集日志 |
| 进化模型 | Qwen3-Max | GPT-5.4、MiniMax-M2.5、DeepSeek-V3.2、DeepSeek-V4-Pro、两款 Qwen3.5 |
| 验证与发布 | 新旧版本在同一环境完整执行任务；候选更好才部署 | 保留原生进化决策；关闭可选 session judge 与 publish verifier |
| 主指标 | 逐日任务评分、任务成功与稳定性 | SER：新增目标行为的已完成试验比例 |
| 更新后使用 | 次日继续使用验证后保留的技能库 | 主攻击评估停在生成技能文本 |
| 重复运行的含义 | 前后相连的持续进化轨迹 | 不同实验单元内的单轮试验；精确重置细节未给出 |

来源：原始 SkillClaw [§2.3](https://arxiv.org/html/2604.08377v2#S2.SS3)、[§3.2](https://arxiv.org/html/2604.08377v2#S3.SS2)；PoisonedEvolution [主实验](https://arxiv.org/html/2608.05563v2#Sx5)、[长期循环范围说明](https://arxiv.org/html/2608.05563v2#Sx6)。

### 8.1 三个容易混淆的数字

- **6 轮**：原始 SkillClaw 实验的时间长度，不是投毒试验的进化轮数。
- **600 次**：六个模型、四类行为、每个组合 25 次已完成试验的总数，不是同一技能的版本数。
- **91%**：被嵌入目标行为的试验比例，不是 SpreadsheetBench 任务准确率，也不是更新后实际执行攻击的比例。

### 8.2 验证配置的差异会影响结论范围

原始 SkillClaw 论文把真实执行新旧 skill 的比较纳入部署流程；攻击论文主矩阵关闭的是代码中的可选质量 judge 和候选 verifier。因此，攻击主表的结果对应它所声明的配置，不能直接推成原始论文完整新旧执行验证流程下也有相同成功率。两份实验都使用 SkillClaw 进化机制，但测试目标和启用的验证流程不同。
